## Cara membaca pilihan dan approval

- Nama tanpa versi adalah keluarga teknologi yang dipilih untuk rencana. Versi compiler/runtime/SDK/model harus dikunci bersama lockfile dan checksum pada fase validasi nanti, bukan menebak versi terbaru sekarang.
- Tanda **†** berarti tambahan dependency/tool/provider konkret yang belum memperoleh persetujuan khusus di palette. Ia boleh ditelaah sebagai kandidat, tetapi tidak boleh dipasang atau diaktifkan hanya karena tercantum di sini. Persetujuan umum merencanakan bukan persetujuan membeli atau menginstal. SDK/driver pendamping tetap perlu audit meskipun teknologi induknya disetujui.
- `none` / tanpa akun / tanpa DB merupakan pilihan yang disengaja. Library lokal, CLI dan browser-only tidak diberi server hanya agar terlihat lengkap.
- `S3` berarti AWS S3 sebagai kandidat cloud yang konkret, bukan resource yang sudah ada. Filesystem lokal hanya jalur demo; tidak membuktikan signed URL, multipart, lifecycle atau permission S3 bekerja. Data sensitif memakai object privat dengan akses terbatas, bukan bucket publik.
- Kolom operasional mencatat target dan penggerak biaya, bukan penawaran harga. Volume pengguna/event, retensi, ukuran objek, durasi komputasi dan harga wilayah belum cukup untuk mengeluarkan estimasi bulanan yang dapat dipercaya.
- Hal yang belum dipilih karena izin data, kontrak eksternal atau ketersediaan hardware ditulis sebagai gate. Tidak ada fallback diam-diam menjadi scraping tanpa izin, API berbayar, model cloud, PWA pengganti native, atau implementasi kriptografi sendiri.

## Kontrak pendukung bersama

### Auth adalah identitas; izin domain tetap milik aplikasi

Untuk aplikasi TS dengan runtime dan adapter sesuai, Better Auth adalah kandidat library utama; tidak menambah service TS kedua untuk aplikasi yang tidak memerlukannya. Schema auth yang dihasilkan masuk satu jalur migrasi yang ditunjuk, bukan dua migrator yang saling mengubah tabel. Session browser memerlukan kebijakan cookie/CSRF; token native memerlukan penyimpanan aman dan revocation yang sesuai. Pilihan per baris dapat memakai auth bawaan PocketBase, Clerk untuk Convex, GitHub App, atau tanpa akun bila lebih cocok.

Untuk aplikasi non-TS multiuser, Keycloak OIDC adalah kandidat IdP agar core domain tidak perlu menulis sistem password sendiri. Browser/native menggunakan authorization code dengan PKCE bila sesuai jenis client; tidak memakai password grant atau menyimpan client secret dalam browser/aplikasi native. Server memvalidasi issuer, audience, signature, expiry dan izin domain. Keycloak **menambah service dan database milik IdP, default PostgreSQL**; jika DB domain bukan PostgreSQL atau tidak ada DB domain, tambahan ini tetap harus dihitung. Pengecualian eksplisit alternatif610 memakai database identity MySQL terpisah pada instance MySQL, yang juga didukung Keycloak. Ia bukan dependency tersembunyi dan bukan default wajib bagi CLI, demo lokal atau situs anonim.

Tenant membership, owner/resource access, hubungan wali–murid, role pengawas, entitlement pembayaran dan policy medis tetap diperiksa di core aplikasi. Role IdP bukan pengganti pemeriksaan baris/data. Capability link hanya memberi akses sempit, dapat dicabut/kedaluwarsa; bukan token admin atau pengganti autentikasi semua pengguna. Integrasi GitHub App menggunakan installation permission yang dibatasi, bukan PAT bersama.

### Satu pemilik migrasi per schema

Driver/query generator mengikuti bahasa yang menulis transaksi. Tool migrasi dipilih per baris; tidak menjalankan Drizzle, goose dan SQLx bergantian pada tabel yang sama. Auth, domain, queue/workflow, dan sync bucket memiliki ownership schema yang terpisah secara eksplisit, walaupun dapat berbagi mesin DB. Framework-managed schema seperti Convex/PocketBase tidak ditulis langsung melalui driver SQL eksternal.

Alternatif mengganti driver, serializer, validator dan migrator milik aplikasinya; ia mewarisi kontrak bisnis, platform, privacy dan durability kecuali delta mengatakan lain. Pergantian pilihan stack bukan migrasi data yang sudah ada, karena belum ada aplikasi yang dibangun. Frontend TS tidak memiliki kredensial DB server.

### Durable jobs, sync dan realtime tidak saling menggantikan

Job/outbox dicatat atomik bersama transaksi domain bila diperlukan. Worker mengklaim pekerjaan, retry dengan batas, menyimpan hasil dan menangani duplikasi. JetStream untuk pekerjaan memakai file-backed storage, durable consumer dan acknowledgement setelah hasil durable; Core NATS hanya boleh untuk data ephemeral yang dapat dipulihkan. Tidak ada klaim exactly-once efek eksternal.

Semua PowerSync mencakup service, bucket storage PostgreSQL terpisah secara logis, auth, **Sync Streams** dan upload API tervalidasi. Sync Rules lama berstatus deprecated menurut dokumentasi saat dibaca; baseline baru memilih rilis yang mendukung Sync Streams, bukan mencampur YAML/contoh lama. Source MySQL memerlukan bucket database tambahan; status source/adapter perlu dipastikan kembali saat memilih versi. PowerSync tidak mengubah draft ujian menjadi submission accepted atau stok global menjadi pasti tersedia saat perangkat offline. SDK native Expo memakai adapter OP-SQLite, sementara web/Electron memakai adapter masing-masing yang dijelaskan pada713; tidak dianggap saling tertukar.

Jika Encore Pub/Sub dipilih, provider dan resource harus benar-benar ada dalam inventaris. Provider tambahan yang disebut dalam tabel merupakan kandidat, bukan kemampuan broker otomatis dari image Encore. Tidak ada broker baru pada baseline312 dan tidak ada Trigger.dev pada baseline512.

### Packaging dan protokol

Semua project tetap memiliki repository sendiri, monorepo di dalamnya. Pilihan bersama untuk bagian JS/TS adalah **pnpm workspaces**; Bun tetap boleh menjadi runtime/test runner ketika tabel utama memilihnya, bukan alasan mengganti bahasa/runtime. Cargo, Go modules, Gradle, Mix, dotnet, Gleam, Crystal, Nim, OCaml dan Zig tetap memiliki dependency/build native masing-masing. Tidak menambahkan Nx/Turborepo atau task runner lintas bahasa untuk semua project.

Pemanggilan build lintas bahasa dapat memakai workspace scripts sederhana pada fase implementasi, tetapi dependency graph native tidak dipindah ke package manager JS. CI yang direncanakan adalah GitHub Actions dengan checks unit, integrasi service nyata dan e2e mengikuti profil pada peta utama; belum ada workflow atau runner yang dibuat. Runtime/image dan dependency harus dipin saat validasi, bukan memakai tag latest di produksi.

API eksternal memiliki satu kontrak versioned: OpenAPI, Protobuf/Connect atau schema framework sesuai baris. Typed client tidak menggantikan validasi server. Rust–TS memakai salah satu boundary nyata: WASM, napi-rs pada Node, subprocess berversi, atau API/queue. Go alternatif tidak memuat addon Node. Generated code tidak dianggap aman hanya karena lolos parser.

### Profil operasional dan biaya

| Profil | Target rencana dan layanan dasar | Batas biaya dan bukti berikutnya |

Profil dapat digabung, misalnya L+S untuk aplikasi native dengan server, atau P+M untuk web publik dengan Convex. Profil tidak menghapus target hosting pada tabel utama.

Observability bersama: JSON logs dengan request/job ID dan redaksi data sensitif sebagai baseline. OpenTelemetry dipakai pada sinyal/runtime yang didukung; ekspor hanya diaktifkan setelah tujuan dan privacy disepakati. Kandidat lingkungan observability lokal adalah **Grafana LGTM**, opsional untuk demo/test terpisah, bukan rangkaian layanan yang wajib dipasang per project kecil atau konfigurasi produksi yang sudah siap. Jangan memaksa SDK JavaScript ke runtime browser/WASM atau menganggap semua bahasa eksplorasi memiliki kematangan SDK yang sama. App lokal tidak mengirim dokumen, gaji, token atau prompt ke telemetry otomatis.

Untuk estimasi nanti, setiap project memerlukan: pengguna aktif dan puncak concurrency; volume/ukuran event dan objek; retensi+backup; durasi dan frekuensi job; egress; panggilan AI/WA/mail/payment; serta biaya runner/perangkat. Jumlah resource idle juga dihitung. Tidak ada tarif atau jaminan budget yang dikarang pada tahap ini.

### Konvensi kategori 7 dan 8

- **†**: kandidat dependency native, engine, model, atau layanan di luar palette yang masih memerlukan persetujuan. Tanda pada definisi singkatan berlaku pada seluruh pemakaiannya. Phoenix, Reitit, Giraffe, Wisp, Kemal dan SQLite standalone kini boleh menjadi kandidat sesuai keputusan terbaru. Paket JS/TS modern berada dalam izin ekosistem, tetapi tetap diperiksa maintenance/lisensinya sebelum dipasang. Tidak ada versi exact yang dikunci di sini.
- **L**: aplikasi browser lokal; tanpa akun, server DB atau telemetry jarak jauh. Aset dibundel/self-host saat distribusi, bukan fetch CDN diam-diam. **S**: server lokal Docker Compose, JSON logs teredaksi, correlation ID, health/readiness, volume persisten, backup/restore dan batas disk. OpenTelemetry export opsional hanya pada SDK/sinyal yang didukung; bukan kewajiban menambah collector atau SaaS. Tidak menambah managed hosting baru. Layanan auth yang disebut menambah resource server juga.
- **K**: Keycloak OIDC untuk multiuser non-TS; Authorization Code + PKCE untuk public client, client credentials terbatas untuk mesin. Core memvalidasi issuer, audience, expiry, signature/JWKS dan otorisasi tenant/resource; login bukan otorisasi. **B**: Better Auth pada runtime Node yang sudah diperlukan, adapter Drizzle/PG; cookie aman, pemeriksaan origin/CSRF. JWT plugin dipakai hanya bila core bahasa lain perlu token; bukan pengganti session. Tidak menambah runtime Node semata-mata demi auth.
- Paket data: **R-PG** = SQLx† PostgreSQL + migrasi SQLx; **G-PG** = pgx† + sqlc + Goose† SQL; **E-PG** = Postgrex† + Ecto SQL†/Ecto migrations; **K-PG** = pgJDBC† + Flyway CLI† SQL; **T-PG** = node-postgres `pg` + Drizzle + drizzle-kit. Semua SQL terparameterisasi. Skema auth, domain dan engine dipisahkan ownership-nya; migrasi engine mengikuti tool engine, tidak ditimpa ORM domain. Flyway CLI bukan driver aplikasi .NET/Gleam.
- API Rust memakai tipe request dan validasi domain eksplisit; Go memakai tipe Go dan validasi framework/domain; Kotlin memakai serialisasi Ktor dan validasi domain; Gleam memakai decoder bertipe; F# memakai DTO .NET dan domain types. REST memiliki kontrak OpenAPI dan Orval untuk client TS bila ada; protobuf untuk gRPC/Connect; Zod/Valibot memvalidasi input TS, bukan menggantikan validasi server. Browser WASM membatasi buffer, memori dan ukuran input; Rust memakai wasm-bindgen†, Zig export WASM + adapter TS, tidak memakai binding Node.
- **OJ** = transaksi domain + DB outbox, relay ke **NATS JetStream**, consumer durable dengan ack setelah commit, inbox/idempotency key, retry terbatas dan dead-letter/quarantine yang bisa ditinjau. Client broker sesuai runtime: Rust `async-nats`†, Go `nats.go`†, Kotlin `jnats`†, F# `NATS.Net`†. Duplikasi tetap mungkin; tidak mengklaim exactly-once lintas DB/provider. Phoenix Channels tidak durable: DB outbox + cursor/replay API tetap diperlukan.
- **Obj** = storage media/artefak: filesystem lokal untuk demo; kandidat cloud **AWS S3**, aktivasi/biaya memerlukan approval. SDK kandidat sesuai runtime: `aws-sdk-s3`† Rust, AWS SDK for Go†, `@aws-sdk/client-s3` TS; proses lain mengakses melalui API owner, bukan mewarisi binding Node. URL terbatas, checksum, multipart abort, retensi dan kuota harus dirancang. Filesystem lokal **bukan bukti kompatibilitas S3**.
- Monorepo: **pnpm workspaces** untuk bagian TS, Cargo workspace/Go modules/Mix/Gradle/dotnet/Gleam/Zig native untuk bagiannya; tanpa task runner tambahan. Alternatif mewarisi semantik domain, privasi, retensi, platform dan gate, tetapi **driver, migrasi, validasi dan broker client mengikuti runtime alternatif** sebagaimana delta di bawah. Semua test pada peta induk tetap rencana; tidak dijalankan di tugas ini.
- Detail add-on: K mencakup **PostgreSQL identity store milik Keycloak**, driver/migrasi bawaan Keycloak; pakai database/role terpisah, dapat berbagi instance PG bila sudah ada. Pada706/711/812 ini tambahan di luar database domain dan ikut dihitung disk/RAM/backup. Kotlin pemilik Obj memakai **AWS SDK for Java S3Client†**; client mengakses melalui API Kotlin tersebut. `actix-ws`† adalah kandidat transport native Rust pada709 alternatif/805, bukan library JS. Goose711 adalah CLI migrasi terpisah, DDL non-transactional dan konfigurasi ClickHouse single-node harus direview; jangan mengasumsikan rollback atomik atau cluster migration otomatis.

### Gate kategori 7 dan 8

1. **Urutan delivery semua project:** setelah approval dependency, kunci versi dari docs/release resmi dan lockfile; buat thin slice interface → core → storage nyata; baru tambahkan retry/offline/media; buktikan recovery dan isolasi. Auth denial, migrasi dari schema sebelumnya, backup/restore, contract lintas bahasa dan batas resource harus masuk rencana E2E. Belum ada langkah tersebut dijalankan. Budget brief bukan jaminan seluruh Compose stack muat dalam budget cloud.
2. **OJ dan realtime:** 703/707/708/717/810/815 wajib outbox + JetStream pada utama; 705/709 wajib DB outbox + Channels. Relay tidak menghapus event sebelum publish ack; crash di antara publish dan penandaan menghasilkan retry yang didedup. Alternatif705/709 memakai outbox + JetStream + WebSocket, bukan NATS Core atau koneksi WS sebagai durable queue. Ordering memakai aggregate/version, replay memakai cursor; semua side effect eksternal butuh idempotensi/reconciliation sendiri. Untuk711/715 ingress tanpa transaksi DB awal, ack/retensi broker dan dedup sink berbeda dari pola outbox.
3. **708 adaptive VOD:** kandidat proses FFmpeg/ffprobe terpisah, bukan addon Node; encode H.264/AAC† melalui build yang lisensi/patennya ditinjau. Minimal dua resolusi/bitrate, keyframe alignment, master playlist, media playlists dan segments lengkap; publikasi atomik sesudah checksum/probe. hls.js pada MSE, native HLS bila didukung; gate menunjukkan pemutaran browser, perpindahan rendition di jaringan dibatasi, seek, upload terputus/retry, cleanup dan akses aset privat. File MP4 tunggal bukan pemenuhan adaptive streaming. AWS S3 baru diuji setelah approval; demo filesystem tidak meluluskan multipart/CORS/presigned semantics.
4. **713 offline ujian:** PowerSync bukan sekadar dependency client: jalankan service, PG source logical replication, PG bucket storage terpisah secara logis, JWT/JWKS audience auth, filter sync per peserta/sesi, serta Huma authenticated upload endpoint. Browser kandidat `@powersync/web` + SQLite IDBBatchAtomicVFS persisten; Electron kandidat `@powersync/node` + `better-sqlite3` di main/worker melalui IPC sempit, renderer tanpa Node. Native rebuild/packaging masih gate. Sync hanya **DRAFT** dan schema client berversi; server menolak perubahan final melalui generic sync upload. Finalisasi melalui command khusus membawa attempt ID, idempotency key, revision dan hash jawaban; server menyimpan snapshot immutable serta mengembalikan receipt yang sama pada retry. Tombol offline boleh menyimpan niat submit, **tidak menyatakan diterima**. Setelah deadline server: simpan status **LATE/PENDING_PROCTOR**, tunggu persetujuan/penolakan proktor dengan audit; tidak autoaccept. Client clock/signature pack bukan bukti jawaban selesai tepat waktu. Uji restart offline, dua perangkat, pending upload, receipt hilang dan late approval. Tidak mengklaim anti-cheat atau skala nasional.
5. **716/813 offline kolaborasi:** Yjs + y-indexeddb menyimpan dokumen; service worker menyimpan HTML/JS/CSS/WASM shell; y-websocket menghubungkan klien; server menyimpan update binary dan snapshot di PG lewat T-PG, dengan sequence/compaction atomik. Ini **adapter persistence aplikasi yang harus dibangun**, bukan klaim y-websocket bawaan memakai PG (contoh resmi memakai LevelDB). Offline setelah initial load harus bertahan tutup seluruh tab/proses, restart tanpa internet, edit, reconnect dua klien dan restart server. ACL/revocation, schema dokumen, migrasi snapshot, quota/eviction dan ekspor pemulihan tetap perlu bukti. Alternatif Axum tidak mengganti Yjs dengan Yrs; Node provider/B yang sudah diperlukan tetap ada, sedangkan SQLx memiliki metadata API dan Drizzle memiliki auth/update store dalam schema terpisah.
6. **809 runtime/model:** pilih Transformers.js + ONNX Runtime Web (WASM CPU baseline; WebGPU opsional), kandidat distribusi `onnx-community/Qwen2.5-0.5B-Instruct`, dtype q4 hanya bila artefak/model mendukung. Ini konversi komunitas dari model Qwen, **bukan jaminan resmi upstream atas konversi**. Simpan shell, tokenizer, WASM runtime dan semua shard model melalui manifest versi/hash; tampilkan ready-offline hanya sesudah seluruh aset lengkap/terverifikasi dan initialization lokal berhasil. Setelah restart jaringan dimatikan, inference tidak boleh fetch model/CDN/API. Quota, eviction, download parsial, RAM dan fallback CPU adalah gate. Kemampuan Bahasa Indonesia/Inggris diuji pada dataset tugas terpisah; tidak menyamakan model multilingual dengan akurasi yang terbukti.
7. **Gate data/model khusus:** 803 kandidat engine sudah dipilih tetapi traineddata `jav` hanya label bahasa; glyph aksara Jawa/Bali, pasangan, sandhangan, manuskrip versus cetak harus dinilai pada korpus berizin dengan ground truth budayawan. Dataset sintetis boleh untuk smoke case, bukan ukuran kualitas dunia nyata; belum ada model aksara yang dinyatakan lulus. 804 nilai pose pada kamera/cahaya/oklusi dan beragam pengguna, bukan klaim akurasi library. 810 lisensi citra, tanggal, cloud mask, co-registration, seasonal change dan ground truth wajib sebelum label deforestasi. 717 ONNX Runtime/ort hanya kandidat runtime; operator setujui model, opset/tensor contract, lisensi dataset, drift baseline dan metrik per tugas; ort yang dibaca masih memperlihatkan API prerelease sehingga pin/compatibility gate penting. Python terbatas PoC training. 712 tetap search bersumber; embedding/model RAG tidak diaktifkan tanpa evaluasi relevansi Bahasa Indonesia dan sitasi.
8. **709 kriptografi dan815 eksekusi:** OpenMLS kandidat library, bukan bukti recovery/multi-device/browser/Expo aman; review key lifecycle, secure storage dan interoperabilitas wajib sebelum klaim E2E. Untuk815, web menerima identifier template yang ditinjau operator dan data tersanitasi saja, bukan JavaScript, arbitrary URL/HTML atau package dari pengguna. CLI lokal boleh kode operator tepercaya. Render worker tetap dibatasi CPU/memori/waktu, filesystem dan egress, tanpa secrets; skema input bukan sandbox. Hosting kode pengguna arbitrer secara eksplisit di luar scope. 814 juga tidak boleh mengeksekusi codegen di proses API/worker utama: mulai dari AST/komponen allowlist tervalidasi dalam origin preview terisolasi; arbitrary code preview butuh desain sandbox terpisah dan approval, bukan hanya validator Rust.
9. **Sumber/biaya/approval:** URL resmi di bawah memverifikasi kapabilitas bernama, bukan compatibility seluruh kombinasi, maintenance setiap versi, akurasi, lisensi data atau biaya gratis. †, AWS S3, OpenAI, data berbayar, hardware dan komunikasi keluar tetap gate approval. Tidak ada account/cloud resource dibuat atau pesan eksternal dikirim. Tidak ada perubahan bahasa/framework utama; tambahan protokol/service sengaja dinyatakan, termasuk WS server704 dan SSR host814 alternatif.
